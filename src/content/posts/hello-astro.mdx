## 为什么又要折腾一次

旧站点是 Hexo + 安知鱼主题。搭的时候觉得挺好：配置一改，插件一装，两天就有个像模像样的博客。问题出在两年后：

- 评论后端挂过一次，页面看着正常，其实读者发不出评论；
- 主题功能越开越多，首页光 `<script>` 就有二十多个；
- 想在文章里插一个自定义组件，得写一堆 HTML 字符串。

<Callout type="note">
最后一条是决定性的。我想要的其实不是“一个博客系统”，而是“一个能按自己想法排版的地方”。
</Callout>

## 为什么是 Astro

选它有三个很实际的理由。

**第一，默认零 JavaScript。** Astro 把每个页面编译成静态 HTML，除非你显式写 `<script>`，否则不会有框架运行时被打包进去。对一个以文字为主的博客，这一条就够了。

**第二，Markdown 就是组件。** 我可以在 `.mdx` 文件里直接写：

```mdx
## 本月读的书

<BookList items={recentReads} />

上面的说法有个前提：<Note>这个结论只在小样本下成立。</Note>
```

翻译成 Hexo 的话，这需要写插件或者手搓 HTML。

**第三，类型安全的内容模型。** Astro 的内容集合要求你为 frontmatter 定义 schema，写错字段构建就会报错：

```ts
const posts = defineCollection({
  loader: glob({ pattern: '**/*.md', base: './src/content/posts' }),
  schema: z.object({
    title: z.string(),
    date: z.coerce.date(),
    tags: z.array(z.string()).default([]),
  }),
});
```

看起来很啰嗦，但它拦住了一次真实的错误：我把 `date: 2026-10-19` 写成 `2026-19-10`，构建直接失败，而不是在页面上显示一个奇怪的日期。

## 新版留下了什么

做减法比做加法难。这次只保留了这些：

| 模块 | 保留 | 说明 |
| --- | --- | --- |
| 文章列表 | 有 | 按时间倒序，日期用等宽字体对齐 |
| 归档 | 有 | 按年份分组，一眼看完写了多少 |
| 标签 | 有 | 没有分类层级，标签足够 |
| 目录 | 有 | 只在长文里出现，桌面端吸附在右侧 |
| 深色模式 | 有 | 跟随系统，可手动切换 |
| 评论 | 待定 | 先把内容写好，评论后面再接 |
| 音乐播放器 | 无 | 从没在别人博客上开过 |
| 背景立绘 | 无 | 好看，但和文字抢注意力 |

> 判断标准很简单：如果一个功能我从没在自己喜欢的博客上用过，那它大概也不该出现在这里。

## 一点代价

换成 Astro 之后，写文章的流程变了：

1. 新建 `src/content/posts/xxx.md`；
2. 写 frontmatter 和正文；
3. `npm run dev` 本地看效果；
4. 提交、推送，GitHub Actions 自动构建部署。

比 Hexo 多了一步“看效果”，但换来的是排版完全可控。对一个要长期写的地方，这笔交易划算。
